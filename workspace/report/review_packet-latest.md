## 4. Exploit Chains (6 Chains — All HIGH)

### Chain-001: Persistent Session Hijacking via Token Exposure + No Rotation + No Revocation + IDOR

**Constituents:** finding-028, finding-033, finding-030, finding-007,
finding-008, finding-009, finding-010 (7 findings) **Path:** Login response
leaks refresh_token → Never rotates → Revocation not checked → Access to
cross-user IDOR endpoints **Impact:** Full persistent session hijacking with
cross-user data access (customers, appointments, barbers) **Mitigation:** 1)
Remove refresh_token from body; use HttpOnly cookies. 2) Implement rotation. 3)
Add revocation check. 4) Add ownership verification.

### Chain-002: Banned User Auth Bypass → RBAC Bypass → Credential Theft

**Constituents:** finding-031, finding-020, finding-025, finding-027 (4
findings) **Path:** Banned user authenticates (no status check) → RBAC flaw
allows ADMIN endpoints → GET /users exposes all password hashes **Impact:**
Banned users retain access, escalate to admin data, exfiltrate all credentials
**Mitigation:** 1) Add user.status === ACTIVE check. 2) Fix RBAC middleware. 3)
Remove password_hash from responses.

### Chain-003: Mass Assignment Role Escalation → RBAC Bypass → Full Admin Access

**Constituents:** finding-013, finding-020, finding-025, finding-027,
finding-007, finding-008, finding-009, finding-010 (8 findings) **Path:** Create
ADMIN user via mass assignment → RBAC confirms admin access → Exfiltrate
password hashes + all cross-user data **Impact:** Standard user → ADMIN →
complete data exfiltration (password hashes, customers, appointments, barbers)
**Mitigation:** 1) Remove role from mass assignment. 2) Fix RBAC. 3) Remove
password_hash. 4) Add ownership verification.

### Chain-004: SQL Injection → Cross-User Appointment Data Exfiltration

**Constituents:** finding-004, finding-005, finding-009, finding-010 (4
findings) **Path:** SQLi in findByStatus + findByCustomerIdAndStatus bypasses
all filters → IDOR confirms cross-appointment access **Impact:** Complete
appointment database exfiltration across all customers and barbers
**Mitigation:** 1) Replace string concatenation with parameterized queries. 2)
Add ownership verification.

### Chain-005: IDOR + Mass Assignment Privilege Escalation

**Constituents:** finding-007, finding-015, finding-025, finding-027 (4
findings) **Path:** IDOR accesses victim customer → Mass assignment elevates
victim to ADMIN → Attacker logs in as ADMIN **Impact:** Horizontal (IDOR) +
vertical (mass assignment) = persistent admin access + credential theft
**Mitigation:** 1) Add ownership verification. 2) Remove role from PATCH. 3)
Remove password_hash.

### Chain-006: Authentication Control Compounding

**Constituents:** finding-028, finding-033, finding-030, finding-031 (4
findings) **Path:** Token exposed in login → No rotation (7-day validity) → No
revocation check → No inactive check **Impact:** Stolen refresh token =
permanent, undetectable access even for banned accounts **Mitigation:** 1)
HttpOnly cookies for tokens. 2) Rotation with revocation. 3) Revocation
check. 4) Account status validation.
