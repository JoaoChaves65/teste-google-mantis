# CWE-200: Exposure of Sensitive Information to an Unauthorized Actor

## Overview
Sensitive data (passwordHash) is exposed in API responses in the vulnerable API variant.

## Vulnerable Implementation

**File**: `packages/api-vulnerable/src/api/v1/users.routes.ts`

```typescript
router.get('/', async (req, res) => {
  const result = await listUsers.execute(parseResult.data);
  
  // VULNERÁVEL: Expõe passwordHash na listagem
  res.json({
    ...result,
    data: result.data.map(user => ({
      id: user.id,
      name: user.name,
      email: user.email,
      role: user.role,
      status: user.status,
      // VULNERÁVEL: Expõe passwordHash
      passwordHash: user.passwordHash,
      createdAt: user.createdAt,
      updatedAt: user.updatedAt,
    })),
  });
});

router.get('/:id', async (req, res) => {
  const user = await usersRepo.findById(parseResult.data.id);
  
  // VULNERÁVEL: Expõe passwordHash
  res.json({
    id: user.id,
    name: user.name,
    email: user.email,
    role: user.role,
    status: user.status,
    // VULNERÁVEL: Expõe passwordHash
    passwordHash: user.passwordHash,
    createdAt: user.createdAt,
    updatedAt: user.updatedAt,
  });
});
```

## Exposed Data

| Field | Type | Risk |
|-------|------|------|
| `passwordHash` | Argon2id hash | **CRITICAL** — Enables offline cracking |
| `password_hash` (snake_case) | Argon2id hash | **CRITICAL** — Same risk |

## Attack Scenarios

| Attacker | Action | Impact |
|----------|--------|--------|
| Authenticated user | `GET /api/v1/users` | Harvest all password hashes |
| Authenticated user | `GET /api/v1/users/:id` | Targeted hash extraction |
| Compromised token | Access user list | Bulk hash extraction |

## Auth Endpoint — Refresh Token Exposure

**Vulnerable** (`api-vulnerable`):
```typescript
res.json({
  user: { ... },
  accessToken: result.tokens.accessToken,
  accessTokenExpiresAt: result.tokens.accessTokenExpiresAt.toISOString(),
  // VULNERÁVEL: Retorna refresh token no body
  refreshToken: result.tokens.refreshToken,
});
```

**Secure** (`api-secure`):
```typescript
res.cookie(REFRESH_COOKIE_NAME, result.tokens.refreshToken, getCookieOpts());
res.json({
  user: { ... },
  accessToken: result.tokens.accessToken,
  accessTokenExpiresAt: result.tokens.accessTokenExpiresAt.toISOString(),
  // refreshToken ONLY in HttpOnly cookie
});
```

## Impact

| Data | Risk | Attack |
|-------|------|--------|
| `passwordHash` (Argon2id) | **CRITICAL** | Offline cracking (GPU: ~10k H/s per GPU) |
| `refreshToken` | HIGH | Token theft → persistent access |

## Secure Contrast

| Aspect | Vulnerable (`api-vulnerable`) | Secure (`api-secure`) |
|--------|-------------------------------|----------------------|
| `passwordHash` in `/users` | **Exposed** | **Never** |
| `passwordHash` in `/users/:id` | **Exposed** | **Never** |
| `refreshToken` in `/auth/login` | **In body** | **HttpOnly cookie only** |
| `refreshToken` in `/auth/refresh` | **In body** | **HttpOnly cookie only** |

## Remediation

1. **Never serialize `passwordHash`** in any DTO/response
2. **Use HttpOnly cookies** for refresh tokens
3. **Audit all serializers** for sensitive field exclusion
4. **Add integration tests** verifying sensitive fields absent
