# CWE-285: Improper Authorization (Broken Role Authorization)

## Overview
Broken Role-Based Access Control (RBAC) allows lower-privilege users to access admin-only endpoints.

## Vulnerable Implementation

### Vulnerable RBAC Middleware
**File**: `packages/api-vulnerable/src/http/middleware/vulnerableRbac.ts`

```typescript
export const vulnerableRequireRole = (...allowedRoles: UserRole[]) => {
  return (req: VulnerableAuthenticatedRequest, res: Response, next: NextFunction): void => {
    if (!req.user) {
      res.status(401).json({ error: 'Not authenticated' });
      return;
    }

    // VULNERÁVEL: Permite que CUSTOMER acesse endpoints ADMIN se souber a URL
    // VULNERÁVEL: Não valida corretamente a hierarquia de roles
    const userRole = req.user.role;
    
    // VULNERÁVEL: Se o usuário for ADMIN, permite tudo (correto)
    if (userRole === UserRole.ADMIN) {
      next();
      return;
    }
    
    // VULNERÁVEL: Se for BARBER, permite acessar endpoints de CUSTOMER e BARBER
    // mas NÃO valida ownership dos recursos
    if (userRole === UserRole.BARBER) {
      if (allowedRoles.includes(UserRole.BARBER) || allowedRoles.includes(UserRole.CUSTOMER)) {
        next();
        return;
      }
    }
    
    // VULNERÁVEL: Se for CUSTOMER, permite acessar endpoints de CUSTOMER
    if (userRole === UserRole.CUSTOMER) {
      if (allowedRoles.includes(UserRole.CUSTOMER)) {
        next();
        return;
      }
    }
    
    // VULNERÁVEL: Retorna 403 apenas se não corresponder a nenhuma regra
    // Mas não valida ownership dos recursos (IDOR)
    res.status(403).json({ error: 'Insufficient permissions' });
  };
};
```

### Secure RBAC Middleware (api-secure)

```typescript
// packages/api-secure/src/http/middleware/rbac.ts
export type UserRole = 'CUSTOMER' | 'BARBER' | 'ADMIN';

export const requireRole = (...allowedRoles: UserRole[]) => {
  return (req: AuthenticatedRequest, res: Response, next: NextFunction): void => {
    if (!req.user) {
      res.status(401).json({ error: 'Authentication required' });
      return;
    }

    const userRole = req.user.role as UserRole;
    if (!allowedRoles.includes(userRole)) {
      res.status(403).json({ error: 'Insufficient permissions' });
      return;
    }

    next();
  };
};

export const requireAdmin = requireRole('ADMIN');
export const requireBarberOrAdmin = requireRole('BARBER', 'ADMIN');
export const requireCustomerOrAbove = requireRole('CUSTOMER', 'BARBER', 'ADMIN');
```

## Root Cause Analysis

### Vulnerable Implementation Flaw
```typescript
// vulnerableRbac.ts - FLAWED LOGIC
if (userRole === UserRole.CUSTOMER) {
  if (allowedRoles.includes(UserRole.CUSTOMER)) {
    next(); // ALLOWS CUSTOMER if CUSTOMER in allowedRoles
    return;
  }
}
```
**Problem**: `allowedRoles` for admin endpoints = `[UserRole.ADMIN]`. But the logic checks `allowedRoles.includes(UserRole.CUSTOMER)` which is `false`, so it should block. 

**Actual Bug**: The vulnerable middleware is NOT applied to admin endpoints! The routes simply don't use `vulnerableRequireRole('ADMIN')` — they either use no RBAC or use `vulnerableRequireRole('ADMIN', 'BARBER', 'CUSTOMER')`.

### Actual Route Configurations (api-vulnerable)

```typescript
// users.routes.ts - VULNERABLE

router.post('/', async (req, res) => { ... });  // NO RBAC!

// transactions.routes.ts - VULNERABLE
```

## Root Cause Analysis

| Factor | Vulnerable | Secure |
|--------|------------|--------|
| Admin endpoints unprotected | YES | NO |
| RBAC middleware on all routes | NO | YES |
| Role hierarchy enforced | NO | YES |
| Ownership validation | NO | YES (separate middleware) |

## Remediation

1. **Apply RBAC middleware to ALL routes** — not just some
2. **Use `requireAdmin()`** for admin-only endpoints
3. **Apply ownership checks** (`checkCustomerAccess`, `checkBarberAccess`) for resource-specific access
3. **Add integration tests** verifying 403 for unauthorized roles
