# CWE-639: Authorization Bypass Through User-Controlled Key (IDOR / BOLA)

## Overview
Insecure Direct Object Reference (IDOR) / Broken Object Level Authorization (BOLA) allows unauthorized access to resources by manipulating object identifiers in requests.

## Vulnerable Implementation

### Customer IDOR
**File**: `packages/api-vulnerable/src/api/v1/customers.routes.ts`

```typescript
// GET /api/v1/customers/:id — NO ownership check
router.get('/:id',
  vulnerableRequireRole(UserRole.ADMIN, UserRole.BARBER, UserRole.CUSTOMER),
  async (req: VulnerableAuthenticatedRequest, res) => {
    const customer = await getCustomer.execute({ id: parseResult.data.id });
    // NO ownership check — any authenticated user can access any customer
    res.json({ ...customer });
  }
);

// PATCH /api/v1/customers/:id — NO ownership check
router.patch('/:id',
  vulnerableRequireRole(UserRole.ADMIN, UserRole.BARBER, UserRole.CUSTOMER),
  async (req, res) => {
    const customer = await updateCustomer.execute({ id: paramsResult.data.id, ...input });
    // Customer can update ANY customer's data
  }
);
```

## Attack Scenarios

| Attacker | Victim | Action | Endpoint | Result |
|----------|--------|--------|----------|--------|
| Customer A | Customer B | Read | `GET /customers/:id` | Full customer data leak |
| Customer A | Customer B | Read | `GET /appointments/:id` | Appointment details leak |
| Customer A | Customer B | Write | `PATCH /appointments/:id/status` | Cancel/modify victim's appointment |
| Barber A | Barber B | Read | `GET /barbers/:id` | Barber profile leak |
| Any User | Any User | Read | `GET /users/:id` | Full user data + **passwordHash** |

## Secure Contrast (api-secure)

```typescript
// packages/api-secure/src/api/v1/customers.routes.ts
async function checkCustomerAccess(req: AuthenticatedRequest, customerId: string) {
  const customer = await customersRepo.findById(customerId);
  if (!customer) return { allowed: false, notFound: true };

  const userRole = req.user!.role as UserRole;
  const userId = req.user!.sub;

  if (userRole === 'ADMIN') return { allowed: true, customer };
  if (userRole === 'CUSTOMER' && customer.userId === userId) return { allowed: true, customer };
  if (userRole === 'BARBER') {
    // Check barber-customer relationship via appointments
    const hasRelation = appointments.data.some(a => a.customerId === customerId && a.barberId === barber.id);
    return { allowed: hasRelation, customer };
  }
  return { allowed: false };
}

// Used in every route:
router.get('/:id', requireRole('ADMIN', 'BARBER', 'CUSTOMER'), async (req, res) => {
  const access = await checkCustomerAccess(req, parseResult.data.id);
  if (access.notFound) throw AppError.notFound('Customer', id);
  if (!access.allowed) return res.status(403).json({ error: 'Access denied' });
  // ... return data
});
```

## Secure Contrast: RBAC Matrix

| Endpoint | Secure (api-secure) | Vulnerable (api-vulnerable) |
|----------|---------------------|----------------------------|
| `GET /customers/:id` | CUSTOMER: own only, BARBER: related, ADMIN: all | **All roles: any ID** |
| `PATCH /customers/:id` | CUSTOMER: own only, BARBER: related, ADMIN: all | **All roles: any ID** |
| `GET /appointments/:id` | Owner/barber/admin only | **All authenticated** |
| `PATCH /appointments/:id/status` | Owner/barber/admin only | **All authenticated** |
| `GET /barbers/:id` | Owner/admin only | **All authenticated** |
| `GET /users/:id` | ADMIN only | **All authenticated** |

## Impact

| Impact Area | Severity |
|-------------|----------|
| **Confidentiality** | Customer PII, appointment details, barber profiles, **passwordHash** |
| **Integrity** | Appointment status manipulation (cancel/confirm) |
| **Scope** | Cross-customer, cross-barber, cross-user data access |

## Detection & Remediation

### Detection
- Check for ownership validation middleware on all `:id` routes
- Verify RBAC middleware is applied correctly
- Scan for direct repository calls without access checks

### Remediation
1. Implement `checkCustomerAccess`, `checkBarberAccess`, `checkAppointmentAccess` middlewares
2. Apply `requireRole('ADMIN')` on admin-only endpoints
3. Filter list endpoints by ownership/role
5. Add integration tests verifying 403 on cross-entity access
